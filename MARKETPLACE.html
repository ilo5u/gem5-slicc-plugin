Short Description

Language support for gem5 Ruby SLICC: highlighting, smart completion, cross-file navigation, and call-site discovery.

Description

Read, write, and explore gem5 Ruby cache-coherence protocols in CLion and IntelliJ IDEA. SLICC / gem5 Ruby Language Support brings syntax and semantic highlighting, context-aware completion, parameter information, and source navigation to .sm and .slicc files.

Follow transitions to their actions, navigate between function declarations and definitions, and jump back to the exact statements that call a function. Follow external SLICC type declarations to reachable C++ definitions. Include-aware lookup and machine, member, and lexical scopes help distinguish similarly named symbols across protocol files. Inside peek and enqueue, message-variable types drive relevant member suggestions.

Built for developers and researchers working on the gem5 Ruby memory subsystem. This plugin supports the SLICC protocol language, not the Ruby programming language.

Features

  • Syntax and semantic highlighting — Distinguish SLICC keywords, types, machines, actions, functions, enumeration members, and fields. Customise colours in the IDE's SLICC colour scheme.
  • Additional attributes and built-ins — Highlight and complete block_on and format like main and desc. Recognise DPRINTF, DPRINTFN, and APPEND_TRANSITION_COMMENT as built-in calls, independently of the 30 reserved words.
  • Debug-flag completion and format checks — Suggest literal DebugFlag and CompoundFlag names from related Ruby build sources for the first DPRINTF argument. Report missing flags and known-source unknown flags. Check literal DPRINTF / DPRINTFN format argument counts, including escaped percent signs and star width/precision arguments; DPRINTFN takes no flag.
  • Transition and call diagnostics — Report missing transition actions and later duplicate state/event pairs in machine/include order. Report missing visible free or supported scoped functions without treating an overload argument mismatch as a missing function; dot-member errors remain type-aware member diagnostics.
  • Description documentation — Show a declaration's desc on hover or with Quick Documentation (Ctrl+Q), including resolved usages of structures, fields, enumerations/constants, functions, and actions. Preserve scopes, escape HTML, retain line breaks, and share descriptions between matching function prototypes and definitions.
  • Complete reserved-word coverage — Highlight and complete all 30 gem5 SLICC reserved words, including global, wakeup_port, check_next_cycle, check_stop_slots, check_on_cache_probe, defer_enqueueing, and case-sensitive OOD. Recognise in_trans, out_trans, and main as attribute keywords alongside interface and desc.
  • External SLICC types → C++ definitions — Navigate from structure names marked external="yes" and external_type declaration names to reachable gem5 C++ type definitions and supported aliases. Respect namespaces, external_name, and Ruby source-root boundaries; report missing definitions as errors and unavailable source context as warnings.
  • Action ↔ transition navigation — Jump from a transition's action reference to its implementation. From an action declaration, jump to its referencing transition or choose among multiple transitions.
  • Structure fields and enum constants → usages — Select a structure field or enumeration constant declaration to find its concrete usage statements, including reads, writes, initializers, and state/event references in transitions. Jump to the actual usage with file/line context, distinguishing receiver types, inherited members, local shadowing, and machine/include ownership.
  • Function declaration → definition navigation — Resolve calls and separate declarations to matching SLICC definitions, with overload-aware lookup across machine/include and member scopes.
  • Function → calling statements — From a function definition, or a declaration without a SLICC implementation, find concrete calling statements in functions and actions. This also works for declaration-only structure and external_type methods.
  • Readable call-site previews — Show complete multiline statements on one line, with caller, file, and line context. Jump directly for a single statement or choose among multiple statements, then navigate to the actual call. Previews have a configurable length limit, defaulting to 160 characters.
  • Include-aware function completion — Suggest free functions from machine includes, protocol files, and global declarations, with return types and parameter signatures. Prefix completion includes functions such as tagLatency and dataLatency when their declarations are visible.
  • Type-aware member completion — After ., show fields and member functions of the resolved receiver type, including supported interface inheritance chains. Handle chained accesses and comments around member-access operators.
  • Type-aware member error checking — Flag unknown field and method names after . when the receiver type and its visible SLICC interface hierarchy are unambiguous and complete, including external declarations. Respect lexical shadowing, message scopes, reference/pointer parameters, and machine/include ownership; suppress downstream errors after an unresolved chain element.
  • Function-result type checking — Check function results assigned to declared variables or fields, including initializers, and results passed as function arguments. Infer simple variables, fields, nested free/member calls, and parentheses within visible SLICC scopes; report definite nominal-type mismatches and invalid use of void results.
  • Scoped message variables — Suggest implicit in_msg only in peek bodies and out_msg only in enqueue bodies. Infer their types from the second statement argument, respecting nested bindings, and flag out-of-scope usage. Explicit function parameters named in_msg or out_msg take priority throughout the function, including nested message blocks, and use their declared types for resolution, completion, navigation, and highlighting.
  • Function parameter information — View overload signatures and the active argument with Ctrl+P, or automatically when typing ( after a function name.
  • Reference parameters — Recognise parameters such as CHIRequestMsg & out_msg and WriteMask &mask as single declarations. Preserve reference and pointer modifiers in displayed signatures and declaration/definition matching; use underlying SLICC types for member lookup and supported call-result compatibility.
  • Parameter name inlay hints — Show parameter names before arguments of resolved free-function and member-function calls. Display hints for ambiguous overloads only where candidate names agree; omit unnamed parameters and arguments already named like their parameter.
  • Implicit type inlay hints — Show the inferred type at the first actual use of each scoped in_msg, out_msg, tbe, cache_entry, or address binding, without repeating explicit visible variable declarations, including function parameters named in_msg or out_msg. Respect peek / enqueue message types and action scopes. Toggle parameter-name and type hints independently under Settings → Editor → Inlay Hints → SLICC; calculation waits until indexing finishes.
  • Scope-aware references and Find Usages — Respect preceding local declarations, block visibility, and parameter/local shadowing. Distinguish resolved overloads and same-named symbols owned by different machines or types.
  • Protocol and global symbol lookup — Follow protocol/include relationships and declarations exposed through RubySlicc_interfaces.slicc to navigate across source files.
  • Everyday editing tools — Search symbols by name, browse the Structure View, fold declaration bodies, match braces, toggle comments, and highlight unresolved ordinary identifiers.

Current Limitations

Rename refactoring, automatic code formatting, and live templates are not implemented. Member diagnostics check names exposed by SLICC declarations, not undeclared C++ members. Unknown receiver types, incomplete or cyclic interfaces, ambiguous types, malformed declarations, and indexing defer this name-only check; call-result, parenthesized, and indexed receivers are not inferred for member-name errors. Separate function-result checks use supported SLICC nominal types, not complete C++ conversions, validation of every raw argument, or function-body return-statement checking; unknown expressions, ambiguous type declarations, conflicting overloads, complex operators, and indexing defer these diagnostics. Inlay type hints cover implicit SLICC variables, not arbitrary C++ expressions. The plugin provides editor support; it does not replace the gem5 SLICC compiler or run simulations.

Debug-flag lookup statically reads supported literal build declarations; unavailable or incomplete source context defers unknown-flag errors. Format diagnostics validate argument counts, not argument types, and defer dynamic or unsupported format strings and incomplete calls. Transition and missing-function checks defer ambiguous or incomplete scopes and indexing rather than guessing. Documentation does not borrow an enclosing declaration's description when the selected symbol has none.

External-type lookup follows supported literal Source / MakeInclude / include paths, considering conditional branches together without executing Kconfig, SCons, or a C++ preprocessor. Computed paths and macro-generated definitions may not resolve. C++ member/call navigation is not included.

What's New in 1.4.0

Release date: 2026-10-21.

Diagnostics, Completion, and Documentation

  • Additional attributes and built-ins. Add block_on / format attribute highlighting and completion, plus built-in parsing, highlighting, and completion for DPRINTF, DPRINTFN, and APPEND_TRANSITION_COMMENT. The gem5 reserved-word list remains 30 words.
  • Ruby debug flags. Complete the first DPRINTF argument from literal DebugFlag / CompoundFlag declarations in the related Ruby/Kconfig/SConscript source graph. Report missing flags and unknown flags only when the source context supports a definite result; DPRINTFN does not take a debug flag.
  • Literal format argument counts. Check DPRINTF / DPRINTFN literal format strings against supplied argument counts. Escaped %% consumes none; star width and precision each consume an argument. Nested calls do not split arguments at inner commas. This checks counts, not types; dynamic/unsupported formats and incomplete calls defer diagnostics.
  • Transition consistency. Report unresolved action names and later duplicate state/event pairs after expanding state/event sets and includes in machine order. Preserve machine isolation and cache invalidation; ambiguous/incomplete contexts and indexing defer diagnostics.
  • Missing function names. Report missing visible free and supported scoped functions. Do not misreport an existing function with incompatible arguments as absent, or guess members of unknown receivers; dot-member checking remains separate.
  • Declaration descriptions. Show desc text on hover and in Ctrl+Q documentation at declarations and scope-resolved usages. Support structures, fields, enumerations/constants, functions, and actions; escape HTML, preserve line breaks, and fall back between matching function prototypes/definitions without borrowing descriptions from enclosing declarations.

Correct Default Action Variables

  • Resolve the actual default cache-entry type. Inside actions, navigate implicit cache_entry to the visible primary AbstractCacheEntry implementation, such as CHI's CacheEntry, instead of requiring the name Entry. Omitted main defaults to true; case-insensitive main="false" excludes types such as DirEntry. Preserve machine/include ownership and do not guess missing or ambiguous defaults.
  • Distinguish parameters from implicit bindings. Function parameters and visible local variables named tbe or cache_entry navigate to their declarations. Only implicit action variables navigate to TBE or the primary cache-entry type. Completion, expression and function-call inference, and implicit type hints share the same selected type.

File and Symbol Icons

  • Distinct rounded-square file icons. Recognise .sm files by a blue badge with white SM, and .slicc files by a #9673A6 purple badge with white H. Dark-theme variants reverse foreground and background colours.
  • Lettered declaration icons. Circular badges distinguish actions (a), enumerations (e), functions (f), machines (m), structures (s), and transitions (t). File and declaration icons share font-independent outlined lettering and dedicated light/dark variants.

Type Checking and Inlay Hints

  • Function-result type errors. Check function results in assignments, variable initializers, and arguments to other calls against visible SLICC target types. This is limited SLICC nominal-type validation, not full C++ conversions, every raw argument, or function-body return checking.
  • Type-aware member errors. Report unknown field and method names after . against the uniquely resolved receiver's visible SLICC declaration and complete interface hierarchy, including external declarations. Respect scopes, shadowing, message types, and reference/pointer parameters. Skip unknown or incomplete receiver information and unsupported expressions; avoid cascading errors along unresolved chains. This checks member names, not full C++ types or argument compatibility.
  • Parameter name inlay hints. Show parameter names before arguments of resolved free-function and member-function calls, respecting overloads and machine/include/type scopes. For ambiguous overloads, show only agreed names; omit unnamed parameters and arguments already named like their parameter.

Toggle parameter-name and type hints separately under Settings → Editor → Inlay Hints → SLICC; calculation waits until indexing finishes.

New Navigation

  • Navigate implicit cache entries. Use Go to Declaration on an implicit cache_entry inside an action to open its visible Entry declaration, matching tbe / TBE navigation. Preserve explicit variable shadowing and machine/include scopes.
  • Follow external SLICC types into C++ definitions. Use Go to Declaration on a structure name marked external="yes" or an external_type declaration name to open reachable C++ type definitions and supported aliases. Respect external_name, namespaces, and Ruby source-root boundaries. Missing definitions are errors; unavailable source context produces warnings. Lookup follows supported literal Source / MakeInclude / include paths without executing the build.
  • Navigate from structure fields and enum constants to usage statements. Click a declaration name to jump to its single usage or choose among multiple statements. Include reads, writes, initializers, and transition state/event references; retain type, inheritance, shadowing, and machine/include scope checks. Usage previews share the configurable length limit and jump to the actual identifier location.
  • Navigate from actions back to transitions. Use Go to Declaration on an action's name to jump to the transition that uses it, or select from a list showing transition headers and files.
  • Connect function declarations, definitions, and calls. Calls and separate declarations now navigate to matching definitions across included files, respecting overload signatures and machine/member ownership.
  • Jump from functions to exact calling statements. On a definition name, discover calls inside functions and actions. Declaration-only methods in structure and external_type support the same reverse navigation when no SLICC definition exists.
  • Preview statements instead of caller declarations. Multiline statements appear on one line with file and line information. Different statements in the same caller remain separate; multiple calls within one statement share one candidate. Selecting a candidate opens the actual call location. Preview text defaults to 160 characters and can be adjusted with the IDE VM option -Dslicc.navigation.maxStatementLength=240.

Smarter Completion and Scopes

  • Complete functions from includes. Free-function suggestions now include visible machine, protocol, and global declarations, with return types, parameter signatures, and overloads. Included functions such as tagLatency and dataLatency can be found by their prefixes.
  • Respect explicit and implicit message bindings. Without a same-named function parameter, in_msg is available inside peek and out_msg inside enqueue, taking their types from the second statement argument. Nested bindings are respected and out-of-scope uses are flagged. Explicit function parameters named in_msg or out_msg override implicit bindings throughout the function, including nested message blocks, using their declared types for completion, navigation, references, and highlighting without redundant implicit-type hints.
  • Reference parameter parsing. Keep CHIRequestMsg & out_msg and WriteMask &mask intact as parameters. Preserve & / * modifiers in signatures and declaration/definition matching; use underlying SLICC types for member lookup and supported call-result compatibility.
  • More accurate variable and reference resolution. Locals no longer leak between actions or outside blocks, preceding declarations and shadowing take priority, and Find Usages distinguishes resolved declarations instead of matching names alone.
