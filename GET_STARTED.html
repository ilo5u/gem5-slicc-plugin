Get Started with SLICC / gem5 Ruby Language Support

Edit and explore gem5 Ruby cache-coherence protocols in CLion or IntelliJ IDEA. This plugin supports .sm and .slicc files; it is not a plugin for the Ruby programming language. The navigation features described below require plugin version 1.2.0 or later.

1. Install the Plugin

  1. Open your IDE's Settings → Plugins → Marketplace.
  2. Search for SLICC / gem5 Ruby Language Support and install an available version compatible with your IDE.
  3. Restart the IDE if prompted.

If you are testing a release that is not yet available on Marketplace, install its distribution ZIP using Settings → Plugins → Settings menu → Install Plugin from Disk. For a local 1.2.0 build, select build/distributions/slicc-plugin-1.2.0.zip. Select the plugin ZIP itself, not a source-code archive; do not extract it first.

For the IDE's installation instructions, see Install and manage plugins.

2. Open Your Protocol Sources

  1. Open your gem5 source checkout or protocol source directory as an IDE project.
  2. Keep the protocol's .slicc root, included .sm files, and their relative include paths intact. Include shared interface declarations, such as RubySlicc_interfaces.slicc and its dependencies, in the project when available.
  3. Wait for project indexing to finish, then open a .sm or .slicc file. Syntax highlighting should activate automatically.

No separate language server or gem5 build is required for editor support. Cross-file assistance depends on the declarations and includes available in your project, so opening an isolated file may provide fewer results.

3. Try Completion and Parameter Information

  • Type a keyword or symbol prefix and invoke the IDE's Basic Completion action. Visible free functions include declarations from machine includes, protocol files, and global interfaces. For example, t or d can suggest tagLatency or dataLatency when those functions are declared in scope.
  • Type . after a variable whose type can be resolved to see its fields and member functions.
  • Type ( after a function name to see parameter information, or invoke Parameter Info with Ctrl+P. Overload signatures show the active argument position.

4. Navigate Between Actions, Functions, and Calls

Use Go to Declaration with Ctrl+B or Ctrl+Click on a name:

  • Transition → action: select an action reference in a transition body to open its implementation.
  • Action → transitions: select an action's declaration name to find the transitions that use it.
  • Function call or declaration → definition: open the matching SLICC definition, including definitions in included files. If there is no SLICC definition, a call opens the declaration instead.
  • Function definition → calling statements: select the function's definition name to find its calls inside functions and actions.
  • Declaration-only method → calling statements: select a method name in a structure or external_type declaration when no SLICC implementation exists. Free functions without definitions support this too.

A single matching target opens directly. Multiple targets open a chooser. Function-call candidates show the complete calling statement on one line with caller, file, and line information; selecting one opens the actual call location. Distinct statements in the same caller remain separate, while multiple calls within one statement share a candidate. Matching respects overload signatures and machine/include/type ownership.

5. Use Message Variables in Their Scope

  • Inside an existing peek(queue, MessageType) body, use in_msg. Type in_msg. for members of the second argument's message type.
  • Inside an existing enqueue(queue, MessageType) body, use out_msg. Type out_msg. for members of that message type.
  • Nested blocks inherit the surrounding bindings; an inner matching statement supplies the nearest binding. Usage outside the corresponding body is reported as an error.

Use queue and message-type names declared in your protocol; the names above illustrate the statement shape rather than a standalone protocol.

6. Explore the IDE Tools

  • Find Usages: Alt+F7 on a declaration.
  • Go to Symbol: Ctrl+Alt+Shift+N to search declarations by name.
  • Structure View: Alt+7 to browse machines, ports, actions, transitions, and functions.
  • Comments: Ctrl+/ for line comments and Ctrl+Shift+/ for block comments.
  • Colours: Settings → Editor → Color Scheme → SLICC (gem5 Ruby).

Shortcut examples use the default Windows/Linux keymap. If your platform or keymap differs, invoke the named IDE action or check its configured shortcut.

7. Optional: Adjust Call-Site Preview Length

Call-site labels show up to 160 Unicode characters by default, including an ellipsis when truncated. To use a different limit:

  1. Open Help → Edit Custom VM Options.
  2. Add the following as a separate line, preserving the existing options:
-Dslicc.navigation.maxStatementLength=240

Save the custom options and restart the IDE. This changes only the displayed preview length, not the source statement or navigation target. Remove the option to restore the default. Do not modify the IDE's bundled default VM options file. See Configure IDE JVM options for details.

Troubleshooting and Current Limits

  • No highlighting: confirm the plugin is enabled and the file is recognised as SLICC, rather than plain text or another file type.
  • Missing completion or navigation: check that the declaration, include targets, and relevant protocol files are present in the project and indexing has finished. Function names are not resolved by unrestricted same-name lookup across unrelated machines.
  • No reverse-navigation candidates: this search covers calls inside functions and actions. A declaration with a matching definition opens that definition first; an unused declaration remains its own target.
  • Unresolved names: diagnostics are based on the plugin's available source declarations and supported resolution rules. They do not replace compiler diagnostics.
  • Rename refactoring, automatic formatting, inlay hints, and live templates are not implemented. Invalid member names after . are not currently reported as errors.

The plugin provides language-editing support. Build protocols and run simulations using your normal gem5 workflow.
