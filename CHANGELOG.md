# Changelog

## 1.3.0 — 2026-10-21

This release supersedes the unpublished 1.2.0 draft and includes its planned
features and fixes, complete reserved-word support, file-analysis performance
improvements, inlay hints, reference-parameter fixes, and conservative SLICC
member/function-result type checking. All features previously tracked as
unreleased are included in this 1.3.0 release. See `README.md` for supported
keywords, feature details, and diagnostic boundaries.

### Added

- Add conservative SLICC nominal-type validation for function results in assignments, field/variable initializers, and arguments to other calls, including invalid use of `void` results. Infer simple variables, fields, nested free/member calls, and parentheses within lexical, message, machine/include, and member scopes. Select overloads by argument compatibility rather than the expected assignment type; agreeing candidates can provide a definite return type. Defer unknown expressions, ambiguous type declarations, conflicting overloads, malformed/complex expressions, and indexing. Preserve SLICC call qualifier semantics instead of enforcing C++ pointer/reference conversions. This does not check every raw argument, function-body `return` statements, or complete C++ implicit conversions; member-name diagnostics remain separate.
- Add type-aware errors for unknown field and method names after `.` when the receiver type and its visible SLICC `interface` hierarchy are unambiguous and complete, including external declarations. Respect inheritance, lexical shadowing, message-variable scopes, reference/pointer parameters, and machine/include/type ownership. Check simple receivers and field-access chains; suppress cascading errors after an unresolved chain element. Unknown types, incomplete/cyclic interfaces, ambiguous types, malformed declarations, indexing, and unsupported receiver expressions defer this name-only check rather than guessing; it does not validate full C++ types, undeclared C++ members, or argument compatibility.
- Add declarative parameter-name inlay hints before arguments of resolved free-function and member-function calls. Reuse machine/include/member and overload resolution; show ambiguous overload hints only where candidate parameter names agree, and suppress unnamed parameters and arguments already named like their parameter.
- Add implicit type inlay hints at the first actual use of each scoped `in_msg`, `out_msg`, `tbe`, `cache_entry`, or `address` binding. Respect nearest `peek` / `enqueue` message types and action scopes, and do not repeat types for explicit visible variable declarations.
- Expose independent parameter-name and type controls under Settings → Editor → Inlay Hints → SLICC. Defer hint calculation during indexing.
- Recognize the complete gem5 SLICC reserved-word list, including `global`, `wakeup_port`, the additional `check_*` statements, `defer_enqueueing`, and `OOD`. Add `in_trans` / `out_trans` / `main` as attribute keywords with the same highlighting, parsing, and completion support as `interface` and `desc`.
- Navigate from `structure(..., external="yes")` and `external_type` declaration names to matching reachable C++ type definitions and supported aliases with Ctrl+Click or Ctrl+B. Honor `external_name`, namespace ownership, template-base names, logical-port mappings, and scalar/std exemptions; keep unrelated Ruby roots separate and preserve semantic SLICC reference targets.
- Report missing external C++ definitions as errors and unavailable Ruby source context as warnings. Follow supported literal Kconfig/SConscript relationships, `Source` / `MakeInclude` entries, and transitive includes, including generated protocol-header forwarding. This conservative static graph unions conditional branches without executing the build; computed paths and macro-generated definitions may not resolve. Document the source tree and limitations in `RUBY_CPP_INTEGRATION.md`.
- Navigate from structure-field and enum/state-constant declaration names to concrete usage statements, including reads, writes, initializers, and transition state/event references. Jump directly for one statement or choose from multiple statements with file/line context; reuse multiline previews and configurable Unicode-safe truncation. Keep semantic references pointed at declarations for Find Usages.
- Navigate from function calls and separate declarations to matching definitions, including cross-file includes and overloads. On a definition name, or a declaration with no SLICC definition (including structure/external-type methods), jump to the sole calling statement or choose among multiple statements in functions/actions. Show the complete multiline statement on one line with file/line context and navigate to the actual call offset. Keep separate statements in the same caller; merge repeated calls within one statement. Labels default to 160 Unicode characters including an ellipsis, configurable with the IDE VM option `-Dslicc.navigation.maxStatementLength=240`. Calls to declaration-only functions still navigate to their declarations; keep machine/include/type scopes separate, including shared prototypes with machine-specific definitions.
- Navigate from an action declaration name to the transitions that use it with Ctrl+Click or Ctrl+B. Jump directly for one matching transition or show a chooser for multiple matches, with transition headers and file names; resolve action names within their machine/include scope.
- Without a same-named explicit function parameter, complete implicit `in_msg` only inside `peek` bodies and implicit `out_msg` only inside `enqueue` bodies. Infer each variable's type from the corresponding statement's second argument for member completion and navigation.
- Report implicit message-variable usage outside its corresponding body as an error. Support nested blocks, nearest matching message bindings, and restoration of outer bindings after an inner block ends.
- Add Marketplace HTML listing/release notes and a separate HTML getting-started guide. Synchronize the product description and 1.3.0 What's New into the plugin descriptor, preserving historical release notes.

### Fixed

- Respect local-variable and parameter shadowing when inferring types for member completion, navigation, function overloads, and inlay hints. Prefer explicitly declared visible variables over action implicit defaults.
- Prefer explicit function parameters named `in_msg` or `out_msg` over implicit message bindings throughout the function, including nested `peek` / `enqueue` bodies. Use the declared parameter type consistently for references, completion, navigation, and highlighting; suppress redundant implicit-type inlay hints. Without a matching parameter, preserve the existing corresponding-message-body restrictions and nearest second-argument type inference.
- Parse reference parameters such as `CHIRequestMsg & out_msg` and `WriteMask &mask` as single declarations. Preserve reference and pointer modifiers in signatures and declaration/definition matching; use underlying SLICC types for member lookup and supported call-result compatibility rather than enforcing C++ qualifier conversions.
- Reduce repeated file-analysis work with a shared project protocol/machine/include graph and per-file declaration-name indexes. Reuse external C++ lookup context within each annotation session and create C++ PSI/navigation pointers only when navigating, not while reporting diagnostics. Preserve cancellation and remove unconditional include/index diagnostic output.
- Resolve data members and enum constants through cached machine/include/type scopes rather than first same-named declarations in unrelated machines. Match inherited fields and chained accesses, preserve local/parameter shadowing, and distinguish transition states from same-named events. Do not guess ambiguous unqualified enum constants.
- Resolve function calls across declaration/definition files before choosing an overload. Correct zero-argument calls and retain primitive, scoped, and pointer parameter types when matching signatures; preserve local shadowing and separate member functions from free functions.
- Include visible free functions from machine includes, protocol files, and global declarations in prefix completion. Show return types and parameter signatures, including overloads, for functions such as `tagLatency` and `dataLatency`; use the same visible function set for parameter information.
- Replace the structure view's unavailable implementation base class with plugin-owned tree elements using public interfaces and smart PSI pointers, restoring compilation against the 2026.2 platform.
- Resolve ordinary variables using lexical scope so locals cannot leak between actions or outside their declaring blocks, or be used before declaration.
- Match Find Usages results against resolved declarations so fields and function overloads with the same name are not conflated.
- Support comments and whitespace on either side of `.` in member completion and navigation, including chained accesses.
